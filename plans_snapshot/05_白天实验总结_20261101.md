# 白天实验总结（2026-11-01 上午）

## E-A01-GPU：BMMA wave pair 计数移植（本轮核心任务）

**目标**：把 gbm_count 的 pair 计数核心移植为 tensor core 直接消费基因组位图的 BMMA wave，验证"matrix engine 点亮"叙事扩展到泛基因组主路线。

**结果：PASS（真实 + 5 组合成配置 TSV 逐字节零差异）**

| 实例 | CPU AVX2 | GPU kernel | 加速比（kernel） | GPU e2e | 判据 |
|---|---|---|---|---|---|
| 真实 K. pneumoniae 1992×54590（14.9 亿对） | 28.94 s | 0.677 s | 42.7× | 9.86 s（2.9×，IO 受限 8.9 s） | cmp 零差异（22155477 对） |
| 合成 N=4000 × 54590 | 46.78 s | 0.693 s | 67× | 1.37 s | cmp 零差异 |
| 合成 N=8000 × 54590 | 90.55 s | 0.696 s | 130× | 1.37 s | cmp 零差异 |
| 随机 N=300/1500/2048 | <0.1 s | 0.022 s | — | — | cmp 零差异（raw 全量 + screen 两模式） |

- **kernel 时间在 N=2000→8000 几乎持平（~0.7 s）**：瓶颈是 2.33e7 个 8×8 tile-block 的 fragment 加载（L2 带宽），k-chunk 数（16→63）摊到 4 个 warp 后占比很小。论文 scaling 叙事：固定 M 时对基因组数 N 亚线性。
- **筛法在 host 端逐表达式复刻 gbm_count.cpp**（IEEE double、同序计算、无 fast-math），GPU 只输出上三角 (i,j,c11) 三元组，host 桶排（i 主、j 次）后写 TSV，保证确定性字节序。

### 踩坑记录（CUDA WMMA b1，全部实证闭环）

1. **`bmma_sync` 的累加操作符必须显式传 `bmmaAccumulateOpPOPC`**（枚举唯一合法值=1；默认值声明的 `bmmaBitOpXOR` 是位操作默认值，累加操作符无默认安全值，传 `{}` 得到 0 是未定义行为）。
2. **b1 `load_matrix_sync` 的 `ldm` 单位是"位"不是 uint32**：行地址 = p + i·ldm/8 字节，且每行 128 bit 必须 16B 对齐 → ldm 须为 128 的倍数。vendor 内核传 `W32*32` 与此一致（W32 uint32/行 × 32 bit）。指针偏移另算（uint32 单位），不可混用。
3. **col_major B 片段可直接加载家族主位图行**：8 个家族行（每行 128 bit 基因组位）即 B 的 8 列，C[i][j]=popcount(row_i ∧ row_j)，k 序天然对齐（A/B 同布局置换相消），无需转置。
4. **验证方法**：探针回读（每段 16B 唯一编码 + 单位阵 B 逐 8 位扫描）定位片段映射；raw 模式（c11≥1 全量输出）对小矩阵做穷尽 c11 对拍，比 screen 模式更能暴露计数错误。
5. `fill_fragment`/`store_matrix_sync`（int 累加器，ldm=8）行为正常；上三角 grid.y<grid.x 块早退省一半 block。
